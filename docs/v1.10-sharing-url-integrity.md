# v1.10 — Sharing, URL integrity and source management

This patch builds on v1.9 without changing the locked v1.7/v1.8 UI shell.

## Job URL integrity

New manual/extension/listing saves normalize URLs before persistence. Tracking parameters and fragments are removed; LinkedIn `currentJobId` search-result URLs are converted to a stable `/jobs/view/<id>` URL. `JobListing.normalizedUrl` is unique for new/normalized records.

Before user-driven saves, JobIntel follows safe public HTTP(S) redirects and blocks a confirmed final `404` or `410`. `401`, `403`, and `429` prove that the site exists but automated access is restricted, so they do not masquerade as a missing link. Private/internal addresses are rejected to prevent the verifier from becoming an SSRF primitive.

After deploying the migration, run `npm run db:backfill-url-integrity` once to normalize historical Source domains and listing URLs. Historical conflicts are reported rather than silently merged.

## Job Source URL identity

Job Source names may repeat. The normalized domain is the identity constraint. A full LinkedIn page URL therefore resolves to `linkedin.com` and matches the existing LinkedIn Job Source.

Job Sources can be edited from their workspace Settings tab. Delete hard-deletes an unused user-created source; if historical jobs, runs, organizations or applications reference it, delete safely archives/disables it instead.

## Email sharing

Jobs supports single-job sharing from the drawer and multi-job sharing from table selection. Set `JOB_SHARE_WEBHOOK_URL` to deliver through n8n/SMTP/provider. When unset, JobIntel generates a `mailto:` link and opens the user's local email client.

## Notifications and stages

Smart notifications and top-bar job/application activity now deep-link to the relevant drawer. The Jobs table continues to show the latest application stage and can now be filtered by a specific stage such as Interviewed, Rejected, Offer, or No Response.

## Browser Companion uniqueness

The extension checks the normalized job URL before save. Existing jobs are shown as already saved, duplicate Save actions are disabled, and the backend repeats the check/deduplication so the extension cannot create a duplicate through a race or stale popup state.
